# 课程导演编排调研：把教材讲成"听得进去"的课

日期：2026-09-14 · 调研范围：lib/agent/teach.ts、lib/agent/course.ts、data/teach-scripts 实测讲稿、外部教学设计方法论

## 0. 一句话结论（说人话版）

课听不进去，问题不在句子——句子 0913 已经改短了——问题在编排。三个毛病：

1. **一件事反复讲。** 同一节课里，"EX 10 是十秒过期"讲了 5 遍。学员的感觉是：这我刚才不是听过了吗？
2. **每段一个模子。** 六个片段全是同一个节奏：先立目标、再讲机制、然后举例、最后小结。听到第三段，后面不用听也能猜到。
3. **不许勾人。** 提示词禁止老师卖关子、禁止用故事开场。课就没了"想听下去"的理由。

为什么会反复讲？因为 AI 写每一小段讲稿时，**看不到前面讲过什么**。它只好把每个术语都当成你第一次听，从头解释一遍。

修法就三招（0913 已改好的部分全部保留，不回退）：

1. 让 AI 记住这节课已经讲过什么——讲过的，不许再讲；
2. 不同类型的课用不同的讲法，不再套同一个模板；内容只有三段的量，就讲三段，不硬凑六段；
3. 允许老师开场抛一个具体问题，勾着人听（必须在课内兑现，不许放空炮）；段尾留个扣子接下一段。

下面的文档是给实现用的：证据怎么来的、代码改哪里、怎么验证。不想看细节，看完这一节就够了。

## 1. 场景与问题重定义

用户 0914 原话：

> 我拿到一本教材，内容可能稍微有一点点深，有一点点难以理解。那这时候，能不能帮助用户把它讲解得更有趣一点？既不失内容的真实性，又能让用户学到里面的真正的东西。……这么一个大部头，五百多页，让用户去看，而且还是英文的，几乎不可能。……咱们的目标就是把这种稍微晦涩一点的内容，生动有趣地呈现出来。"有意思"很关键，要让用户听得懂、弄得明白。

场景钉死为：**晦涩长文本（如 578 页英文教材《Game Theory》）→ 有意思、忠实、听得懂的课**。当前 22 门课里教材模式 1 门（Redis 分布式锁实战，7 单元 26 讲），正好是用户本人亲耳听过并按下「没跟上」的那门——以下全部实证来自它。

两个目标词的边界（沿用 [[prompt-wealth-teaching-methods]] 的共识）：
- **有意思 ≠ 包装水**：不是加"翻车""炸裂"，是把内容自身的戏剧性（反例、事故、演进、争议）组织出来。
- **忠实 ≠ 照搬**：镜像教材目录只解决了"讲什么"，没解决"按什么顺序、用什么钩子讲"——书面的知识逻辑 ≠ 听觉的认知逻辑。

## 2. 实证：一门教材模式课程的三份证据

样本：`data/teach-scripts/u-f5a2e05a55_course-d5d3e4de_unit-2_lec-2-2.json`（SETNX+EXPIRE 两步操作：非原子导致的死锁陷阱，0913 新风格讲稿，6 片段 60 拍）。「没跟上」埋点 `data/ops/struggle/2026-09.json` 记录用户在该讲 intro 片段举手。

### 证据一：重复——课不往前走

逐拍统计同一讲内同一名词的"专讲拍"出现位置：

| 内容 | 专讲拍分布 | 次数 |
|---|---|---|
| EX 10 = 十秒过期、崩溃兜底 | 段3、段4×3、段5 | **5 处** |
| NX = 不存在才设置、保证互斥 | 段3、段4×3 | **4 处** |
| value = UUID+线程ID、为解锁校验 | 段3、段4×2、段5×5 | **8 处** |

「参数逐个拆解」（段4）整段 10 拍几乎全是段3 的复述；「订单锁实战写法」（段5）前 9 拍一半在复述段3+段4。**全讲约三分之一的拍数在讲学员刚听过的东西。**逐字重复率（8 字 n-gram，段两两）：段3×段4 = 12%，段3×段5 = 6%——这还没算换措辞的复述（"换句话说"引导的那类恰恰不匹配 n-gram）。

跨讲同样重复：lec-2-2 的开场片段「为什么需要分布式锁」整段重讲 unit-1 lec-1-1 的主题（超卖故事），措辞不同所以 n-gram 只显示 4%，主题级是整段重合。

### 证据二：单调——六段一个模子

- 6 个片段的段首：「这节课我们…」「上一节我们…这一节…」「这一节我们…」×3——同一个开场句式。
- 一讲之内口头禅：「换句话说」×4、「大部分人以为」×3、「就这句，记住」×2。「重点的重量」要求的"先给错误理解再给正确机制"被执行成了每段一次的固定动作。
- 每段内部节奏完全相同：立目标→机制→复述→例子→小结→交棒。听到第 3 段学员已经能预测后面 3 段的一切。**可预测 = 没有听的必要。**

### 证据三：无钩子——悬念被明令禁止

现行提示词（teach.ts TEACH_STYLE / BEAT_SCRIPT_SYSTEM）里有硬禁令：
- 「不要用悬念或翻车故事开头，靠'学完就能用'抓人」
- 「不卖关子、不吓唬人」
- 「禁止表演腔（渲染情绪的语气词、'翻车''炸裂'式的夸张）」

这些是 0912 治"轻飘飘"时下的猛药，把"勾人"的手段也一起禁掉了。而教材内容本身自带最好的戏剧性——Redis 课的蓝图本来就是一条悬疑链（两步加锁死锁 → 原子加锁 → 误删他人锁 → Lua → 看门狗 → 主从失效 → Redlock 争议，每层解决上一层的反例），导演却把它拆成六个均质小节，把故事拆没了。

## 3. 根因：五个编排病（对应代码位置）

1. **导演无记忆（最重）**：`runStartTeaching`（teach.ts:344-414）循环里，每个片段的讲稿生成只带自己的 title/focus（beatUserMsg，teach.ts:360-368），看不到前面片段说过什么 → 每段把同一批术语当首次出现，触发「术语首现三件套」重新解释一遍。**0913 的"关键机制讲两遍"规则在无状态生成下膨胀成了冗余机器：每段的"第一遍"就是同一内容。**
2. **讲师无课程记忆**：`buildLectureContext`（teach.ts:623-641）只带本讲 title/summary，不带前几讲 → 每讲都从零重开动机（超卖故事讲了至少两遍）。
3. **固定五段式模板**：导演提示词硬性规定「片段顺序覆盖：开场动机→核心机制→分步拆解→例子→误区与小结检验」（teach.ts:313），5-6 段硬性下限（`segments.length >= 5` 才不兜底，teach.ts:334）→ 内容只有 3 段的量也硬摊成 6 段。
4. **悬念禁令**（见证据三）：勾人的合法手段被清零。
5. **教材模式缺"翻译"层**：镜像目录（course.ts:99 蓝图提示词教材模式条款）保证了忠实和覆盖，但书的目录是写给能回看的人的；课节生成后再套五段式模板，书的密度没有被重组成"只能听一遍的耳朵能消化的密度"。

蓝图层本身是好的（教研闸门+演进链+结课作品倒推），病集中在讲级编排。**不 retour 全管线，改导演层就够。**

## 4. 外部方法论：六家怎么编排难内容

| 来源 | 核心主张 | 对我们的启示 |
|---|---|---|
| Gagné 九大教学事件 | 第一事件 = gain attention（引起注意），第三 = stimulate recall of prior learning | 我们恰好缺 1 和 3：开场被禁止勾人；导演不知道前面讲过什么 |
| Keller ARCS 动机模型 | Attention / Relevance / Confidence / Satisfaction 四要素缺一不可 | A 被禁令压死；C（信心）正被重复破坏——学员会想"又讲一遍，是不是我没听懂" |
| Mayer 多媒体学习 12 原则 | segmenting（按学员节奏切段）、pre-training（关键概念先预热名字再正式讲）、coherence（删掉一切不服务理解的冗余）、personalization（对话体优于书面体） | coherence/对话体已做（板书预算+说人话）；**pre-training 正是"已解释术语表"的正确用法**：术语在课内预热一次，之后直接用 |
| 好奇心缺口（Loewenstein 信息缺口）+ open loop | 先让学员意识到"自己不知道一个具体答案"，才有听的动机；open loop 是单点最强的 retention 技术 | 把"禁悬念"改成"禁空洞悬念"：钩子必须是本讲会兑现的具体问题 |
| But/Therefore 叙事法则 | 段与段之间用"但是/所以"连接（因果），不用"然后"（并列） | 我们的因果链规则已有，但被均质模板抵消；段间交棒句要用"但是" |
| Kapur productive failure | 先让学员对具体问题尝试并失败，再正式讲解，概念理解和迁移显著优于直接讲授 | checkpoint 可以前置：先问"这版两行代码能上线吗"，学员猜完再讲事故 |

主要来源：[Gagné Nine Events (NIU)](https://www.niu.edu/citl/resources/guides/instructional-guide/gagnes-nine-events-of-instruction.shtml)、[ARCS Model (TAMU)](https://www.tamus.edu/academic/wp-content/uploads/sites/24/2017/07/ARCS-Handout-v1.0.pdf)、[Mayer 12 Principles (DLI)](https://www.digitallearninginstitute.com/blog/mayers-principles-multimedia-learning)、[Segmenting Principle (Cambridge)](https://www.cambridge.org/core/books/multimedia-learning/segmenting-principle/37240877DDA0362355ADB39936027982)、[Open Loop 脚本框架 (Storyflow)](https://storyflow.so/blog/youtube-video-script-template-7-part-framework-retention-2025)、[Kapur productive failure in math (2014)](https://pubmed.ncbi.nlm.nih.gov/24628487/)、[Kapur 官方项目页](https://www.manukapur.com/the-research-project/)。

## 5. 编排框架提案：编剧型导演

回答核心问题："当一个主题给到你之后，该怎么去编排？"——四层规程：

### 5.1 四层规程

**第 0 层 · 课程 = 连续剧**（蓝图，已基本成立）：结课作品是终点（已有）；补一条**主线问题**——学员带着走的那个大问号，长在结课作品最难的那一步上（Redis 课即"多台机器同时改一个数，怎么保证不出事"）。单元=季，讲=集。

**第 1 层 · 每集一问**（导演）：每节课开场 30 秒抛出一个学员此刻答不出的**具体问题**，全讲结尾兑现它。导演不再套固定五段式，**按内容形状选剧本型**（见 5.2）；段数按内容量定（3-6 段），删掉"内容不足硬凑 6 段"的下限。

**第 2 层 · 段间交棒**（状态注入，最大杠杆）：生成本段讲稿时注入两样东西——
- **剧情至今**：前面每段的标题 + 核心一句（各 ≤20 字）；
- **已解释术语表**：前面已讲过、可直接使用的术语清单。
配套规则改写：「术语首现三件套」只对**不在表里**的术语执行；新增硬规则「**本片段只讲 focus 里没被前面讲过的东西；前面已讲的机制直接引用，复述=事故**」。0913 的"关键机制讲两遍"收窄为**只在全讲范围内讲两遍**（第一遍机制语言在它所属的段，复述拍可以仍在该段内），而不是每段各自讲两遍。

**第 3 层 · 段内台词纪律**（0913 全保留）：句长 18-38 字、一拍一件事、板书预算 6-9 条、"记住这句"≤20 字——全部不动。只改段内推进顺序为：接上句 → 抛/接问题 → 机制 → 兑现 → 交棒下段。段尾交棒从"下一节我们来看XX"升级为 mini open loop："到这里你可能想问：崩溃如果发生在两行命令中间怎么办？下一节就出这个事故。"（**But/Therefore 连接，禁止"然后"式过渡**。）

### 5.2 剧本型清单（替代固定五段式）

导演按课节 title/summary/depth_tags/参考资料形状选型，focus 按型的节奏写：

| 剧本型 | 段序列 | 适合 |
|---|---|---|
| **演进型** | 朴素做法 → 踩坑事故 → 修复 → 新坑 → … → 当前最佳实践 | 演进链主题（Redis 锁、工具、协议版本） |
| **陷阱型** | 现象 → 直觉答案 → 为什么错 → 正确机制 → 边界 | 误区集中的主题（并发、安全、性能） |
| **对比型** | A 怎么做 → B 怎么做 → 三维对比表 → 何时用哪个 | 方案选型（Redisson vs Jedis、RAG vs 微调） |
| **操作型** | 目标 → 步骤拆解（每步"为什么"） → 跑通 → 常见报错 | 实操课（结课实操、环境、代码） |
| **原理型** | 问题 → 直觉图像 → 正式定义 → 推导 → 用图像回看定义 | 数学/理论（博弈论均衡、梯度下降） |

### 5.3 "有意思"手段清单（导演可用、按内容选，不强制每段全用）

1. **具体事故冷开场**：钩子来自教材/资料里的真实案例（"库存只剩 1 件，两个实例同时读到 stock=1"——这句已经在讲稿里了，把它提前到第一拍就是钩子）。
2. **先试后教**（productive failure 轻量版）：机制段之前出一道 checkpoint——"这版两行代码能上线吗？"学员猜完再揭晓。
3. **反例驱动**："这行代码看着没问题，但有一个致命时刻"——教材的反例/定理否命题是现成素材。
4. **对比**：错误做法 vs 正确做法（vs/judge 板式已有）。
5. **进度感**：points 步骤轨已有，交棒句可带"四关已过两关"。
6. **口头禅轮换**：「换句话说」「大部分人以为」「就这句」每段最多出现一种，全讲至少换三种表达。

### 5.4 教材模式忠实底线

有意思不豁免忠实：
- 钩子、事故、例子**必须来自教材内容本身**（书里的例子、反例、历史、习题），禁止为了戏剧性编造案例；
- 事实带页码回链（机制已有，保留）；
- 审稿不新增第三把尺子（闸门不膨胀），把"复述不得改变教材结论"并入现有 REVIEW_SYSTEM 的 specific 尺子表述里。

### 5.5 Before / After：同一讲重排示例

**Before（实测，6 段）**：为什么需要分布式锁（重讲上一单元超卖）→ SETNX+EXPIRE 的坑 → 一条命令原子加锁 → 参数逐个拆解（复述上段）→ 订单锁实战写法（复述上两段）→ 误区与小结检验（提前讲 unit-3 内容）。

**After（演进型，4 段）**：
1. **前情+本集问题**：上一讲你在单机上被超卖坑过，也知道正确的锁要过四关。现在写第一版：两行命令，SETNX 占坑，EXPIRE 十秒兜底。——这版代码，能直接上线吗？（checkpoint：猜隐患）
2. **事故**：某天夜里它真挂了：进程在两行命令之间被 OOM 杀掉。SETNX 成功、EXPIRE 没发出去——一把永不过期的锁，全站下单卡死。窗口就在两行命令之间，这叫**非原子**。（兑现钩子）
3. **修复**：一条命令把两件事焊死：SET key value NX EX 10。NX/EX/value 各拆一次（全讲唯一一次），"原子=中间插不进任何命令"。就一句：占坑和设过期要么都成，要么都不成。
4. **实战+交棒**：套进订单 1001 的支付回调，key 怎么起、value 填什么。收尾交棒：这版锁能上生产了吗？还差一步——A 的锁过期后 B 抢到了，A 回来把 B 的锁删了。下一讲就看这个事故。（直连真实存在的下一讲 lec-3-1「误删锁的时序」）

差异：6 段→4 段；参数只拆一次；开场 10 秒有具体钩子；段段推进；结尾钩子直连下一集；教材内容零虚构。

**验证方案**（可测量，不靠体感争论）：
1. `eval/measure-comprehension.ts` 加两个指标：讲内段两两 n-gram 重复率、段首句式/口头禅套路计数；0913 六项指标全部保留。

3. 端到端听感验收仍是用户本人（他是第一验收人）。

## 7. 风险与不做的事

- **不回退理解预算**：句长、一拍一件事、板书预算、"记住这句"全部保留——那是 0913 验证过的成果，本次只动编排不动台词纪律。
