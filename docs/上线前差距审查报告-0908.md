## P0 —— 上线阻断（明天上线前必须解决）

### P0-1 白板课堂播放循环必现崩溃：板书全程空白 ⚠️ 招牌功能失效
- **现象**（截图 11~16）：课堂开讲后，前 ~30 秒能看到少量板书，随后白板永久空白；讲师照常说话、字幕照常滚动，直到本节讲完，板书再没出现过。「课堂步骤」指示条也卡在第一步不动。
- **根因**（已用运行时错误捕获实锤）：`components/board-writer.ts:158`
  ```ts
  api.updateScene({ elements: [...existing, ...els[0]] });
  ```
  `els[0]` 是对象，`...els[0]` 在数组字面量里展开非可迭代对象，**每次执行必抛** `TypeError: els[0] is not iterable`（错误栈：focusBoard ← nextQuad）。该函数负责「镜头对焦」和「翻黑板」；它一抛，播放器 pump 循环整体崩掉，靠 SSE 下一帧才被拉起，循环反复半死重启。镜头从未对焦成功，后续象限的板书写到了视口之外——用户看到的就是「空板子配画外音」。
- **修复**：`[...existing, els[0]]`（一行）。已修复并回归验证通过。
- **教训**：这个 bug 说明白板课堂**没有跑过一次完整的 8 节联调**——首屏象限内容掩盖了翻页路径。

### P0-2 登录验证码在未配置 SMTP 时直接回显到登录弹窗（任何人可登录任何邮箱）
- **现象**（截图 02）：发送验证码后弹窗直接显示「本地开发模式（未配置 SMTP），验证码直接给你：465806」。
- **位置**：`app/api/auth/code/route.ts`（`devCode` 兜底）+ `AuthModal.tsx`（明文展示）。
- **后果**：当前 `.env` 没有 SMTP_*。**如果明天带着这份配置上线，等于无鉴权**——输入任何人的邮箱即可登录其账号、看其全部课程。
- **修复**：服务端 `devCode` 兜底加 `NODE_ENV !== "production"` 闸门；生产未配置 SMTP 时直接拒绝发码并给出明确报错。已修复。**上线前必须在 .env 配好 SMTP**（QQ/163 授权码即可）。

### P0-3 数据没有用户隔离：全体用户共享同一份学习画像和全部对话
- **实测**：用全新账号 `qa.review@test.com` 登录，首页赫然显示**别人的**学习画像摘要（一段 500 字的「API 调用向 Agent 框架循环过渡」画像），侧栏能看到全部 17 门课与全部历史对话（含「导师回应学生爱意」这类测试垃圾）。
- **位置**：
  - `lib/profile.ts`：画像就是全局单文件 `data/profile.json`，无用户维度 → A 的画像会注入 B 的课程生成和白板教学；
  - `app/api/conversations/route.ts` + `lib/store.ts`：对话列表、消息读取完全不过用户；
  - 课程有 `ownerId` 但「无主数据所有人可见」（`app/api/courses/route.ts:17`）——上线时 17 门无主课等于全员可见。
- **修复**：画像按用户分文件（`data/profiles/{userId}.json`，匿名走 `anonymous`）；对话创建时打 `ownerId`，列表/读取按用户过滤；无主课程保留为「官方示例」但要有这个自觉，而不是靠遗留逻辑。画像隔离与对话隔离已修复。
- **附带动作**：`data/profile.json` 这份「假人设」已重置为空——不能让新用户的每一门课都被一个不存在的「入门阶段学习者」污染。

### P0-4 生成中途离开页面 = 进度静默丢失
- **实测**（记录于体验过程）：课程生成到第 2 步时点了别的页面，回来后一切归零——没有「正在生成的课程」的恢复入口，没有提示，服务端留下一个没有 title 的孤儿状态文件（`data/courses/course-1cb39d9c.json` 只有 step/history/sources）。
- **后果**：课程生成耗时 1~3 分钟，用户必然会切页。回来发现没了，直接流失。
- **建议**（上线前至少做其一）：a) 生成期间前端锚定生成视图 + 离开前 `beforeunload` 拦截；b) 服务端 pipeline 与客户端解耦（后台跑完落盘），回到首页显示「你的课程《xx》已生成」。本次未改（动管线，风险大），**强烈建议明天上线后第一个迭代做 b**。

### P0-5 上线清单缺口（配置/合规，非代码）
1. **SMTP 必须配置**（见 P0-2）。
2. **无用户协议/隐私政策勾选**：要收「实名用户」，登录处至少要有同意勾选与协议文本（PIPL 基本要求）。本次未加，建议上线前补简版。
3. **课程集市为空**（截图 18）：Hyperknow 首页下方就是课程集市内容流，我们的集市是一块「集市还空着」。17 门现成课程没有一门被上架。上线前把质量最高的 6~8 门手动写进 `data/marketplace.json`（或做一键「官方上架」）。
4. **测试数据清洗**：历史对话里的测试会话（「导师回应学生爱意」「轻松开场导师待命」等）已归档到 `data/_archive_preload/`；11 门测试课程保留作为集市/记录的填充内容，但**标题重复度高**（3 门都叫「LLM Agent Tool Use 设计模式：…」），建议删到 6 门以内精品。
5. `npm run build`（生产构建）没有验证过——上线前必须跑一遍并冒烟。

## P1 —— 严重（用户可感知的品质问题，本周内修完）

### P1-1 首页第一屏的「气质差距」（对标 hk_agent_home.png）
用户说的「人家更舒服」，拆开是这几件事：
1. **右侧 40% 首屏是死的**：输入卡以下没有任何内容，页面在 y≈470 就结束了。Hyperknow 的输入卡下方紧接着「生成课程时可以用什么主题？」帮助链 + 「课程集市」内容流，页面是满的、有纵深邀请的。**建议**：首页下方铺「课程集市精选」横排卡（数据现成，就是没有入口）。

3. **「MVP」徽章**（`Sidebar`）：明天见实名用户，等于把「半成品」贴脑门上。已删除。

5. **无登录态/积分展示**：Hyperknow 右上有 FREE 套餐、积分、头像、联系创始人。我们登录后只有侧栏底部一行小字。短期可接受，但「谁在用产品」应当在主区可见。
6. **建议 chips 与 placeholder 重复**：输入框 placeholder 已含完整示例，下方三个 chips 又是同样三个例子。chips 应该是「不同于 placeholder 的灵感」，已换掉一组。

### P1-2 蓝图（结构预览）默认视图废掉
- **现象**（截图 07）：react-flow 画布 560px 高，思维导图缩成一小团挤在中偏右，90% 留白，节点文字完全不可读。这是「用户可编辑课程骨架」的核心卖点，现在看起来像 bug。
- **根因**：`BlueprintEditor.tsx:490` 只在 `refitKey`（展开/收起）变化时 fitView；节点是流式陆续到达的，首次渲染时画布为空，fitView 跑了个空。已修复：节点数从 0→N 时自动 fitView，padding 收紧，并在节点流式增长时跟随 refit。

### P1-3 课堂对话面板两处硬伤
1. **Markdown 不渲染**：讲师输出自带 `**加粗**`/代码标记，`CourseSession.tsx:1173` 用纯文本 `whitespace-pre-wrap` 直出，学员全程看「**时机**和**复用**」这种原始星号（截图 15）。主聊天 `MessageItem` 用了 ReactMarkdown，课堂没有——同一个产品两种排版标准。已改为轻量内联渲染（加粗/行内代码）。
2. **自动滚动追不上重点**：打断提问后，学员的问题和讲师的回答被后续 beat 顶出可视区（实测消息 y=-431，截图 16）。功能本身是通的（服务端有作答），但用户大概率「问了却以为没被理」。已改为：新消息与流式草稿变化时强制滚底，打断问答期间暂停 lecture 自动滚动。

### P1-4 课程大纲里 11/32 课节显示「即将上线」
- **现象**（截图 10）：刚生成的课，1/3 课节是灰色「即将上线」。总时长却按 32 节算（「12.6 小时」），承诺与可学内容不符——这是信任杀手。

- **已改**：按钮文案改为内容类型本身（📝 测验 / 🧩 项目）+ hover 说明「此课节为测验/项目环节，随课堂练习开放」；不再使用「即将上线」字样。同时总时长仅累计可学课节（避免虚假承诺）。

### P1-5 课堂顶部三个音频控件语义不清
「语音」（绿胶囊）、「1x」、「聆听」三个按钮挤在一起，用户无法区分「语音开关」「语速」「聆听模式」。**建议**：合并为「🔊 语音开/关」「1x 下拉」，删掉或并入「聆听」；至少补 tooltip。本次已补 tooltip 与 aria-label（未重排，重排建议放到迭代）。

### P1-6 生成完成的「就绪卡」细节
