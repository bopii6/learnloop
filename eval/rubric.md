# LearnLoop 课程生成 Eval 打分表

> 用法：`npm run eval`（全量 10 题）或 `npm run eval -- --only=ml-systematic,cooking-zero --tag=v3`（指定题目）。
> 规则：**改完 prompt 就全量重跑，总分比上次高才采纳，低了就回滚**。打分一半是机器算的（可复现），一半是 LLM 评委按本表打的（换评委模型时分数不可跨模型比较）。

## 一、机器打分（每题满分 6 分，规则写死在 eval/run.ts，完全可复现）

| 检查项 | 满分 | 判定 |
|---|---|---|
| 结构完整 | 2 | 单元数 3-6 得 1 分；每单元课节数 2-5 得 1 分；蓝图走了兜底（单单元 lec-1-1）直接 0 分 |
| 课节标题具体 | 2 | 平均标题长度 ≥ 12 字得 1 分；命中套话黑名单（见下）0 次得 1 分，1-2 次得 0.5，≥3 次 0 分 |
| 细节填充 | 1 | 全部课节有真实摘要（未出现兜底句式"深入讲解「…」"）得 1 分 |
| 无空话摘要 | 1 | 摘要中不出现套话黑名单词得 1 分 |

套话黑名单：掌握核心 / 核心概念 / 深入学习 / 全面了解 / 基本概念 / 基础知识 / 相关知识 / 初步了解 / 深入探讨 / 综合概述

## 二、LLM 评委打分（每题满分 20 分）

评委拿到：完整大纲 JSON + 该题 persona + expect，按以下四个维度各打 0-5 分，并列出 issues：

| 维度 | 考察点 |
|---|---|
| specificity 标题具体性 | 课节标题是否具体到机制/场景/考点，能否一眼看出这节课学什么、学完能做什么 |
| structure_logic 结构逻辑 | 单元之间的递进关系是否合理，先修依赖顺序对不对 |
| audience_fit 受众适配 | 深度、节奏、语言是否贴合该题的 persona（如 70 岁老人 vs 大三学生必须有明显差异） |
| overall 总体印象 | 作为一门要交付的课，你是否愿意把它交给这位学习者 |

评委规则：宁低勿高——拿不准的档位打低一档；至少给出一条 issues。

## 三、总分与采纳规则

- 每题满分 26 分（机器 6 + 评委 20），全量 10 题满分 260
- 每次全量运行后写入 `eval/results/latest.json`；下次运行自动与它对比，输出各题涨跌
- **采纳标准：总分上涨且没有任何一题跌超过 4 分；否则回滚 prompt 改动**
- 成本：runner 记录每题 token 用量，按 `eval/run.ts` 顶部的价目常量折算人民币（DeepSeek 调价后改那两个常量）

## 四、什么时候跑

1. 任何 `lib/agent/prompts.ts` / `course.ts` 里提示词的改动之前：先跑一次存底
2. 改完之后：全量重跑，对比
3. 换模型（LLM_MODEL）：必须重跑，模型和 prompt 是耦合的
